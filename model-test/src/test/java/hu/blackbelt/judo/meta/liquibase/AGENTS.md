# `model-test/src/test/java/hu/blackbelt/judo/meta/liquibase` — dual-engine (EVL vs Java) validation test harness

| File | Purpose |
|---|---|
| `AbstractLiquibaseValidationTest.java` | Shared fixture letting one test body run against both validation engines. Exports `initModel()`, `runValidation(Collection<String> expectedErrors, Collection<String> expectedWarnings)` and protected `liquibaseModelSupport`, `liquibaseModel`, `validatorType`. `initModel()` builds `urn:liquibase.judo-meta-liquibase` and a `LiquibaseModel` named `test`; subclasses must set `validatorType` and call `initModel()` before building content. EVL branch runs `liquibase.evl` with empty expected collections on purpose, catches `EvlScriptExecutionException` and compares only `UnsatisfiedConstraint` *names*, because EVL reports `Name\|message` while Java reports bare names. Mismatch throws `LiquibaseValidationException`; null `expectedWarnings` means warnings are ignored. |
| `LiquibaseValidationPerformanceTest.java` | Scale benchmark over a generated `databaseChangeLog` of `NUM_CHANGE_SETS`=1000 ChangeSets, each one `CreateTable` with `COLUMNS_PER_TABLE`=10 columns (~12,000 elements) under `urn:liquibase.performance-test`. Tests `testJavaValidatorPerformance` (sequential then parallel `LiquibaseValidator.validateLiquibase`), `testEvlValidatorPerformance`, `testValidatorComparison`. Timings are only logged — no assertion fails on slowness, so this test never gates a build. |
| `ValidatorType.java` | Enum discriminating the two validation engines for `@EnumSource` parameterized runs. Constants `EVL` (dispatches to `LiquibaseEpsilonValidator`) and `JAVA` (dispatches to `LiquibaseValidator`). `AbstractLiquibaseValidationTest.runValidation` throws `IllegalStateException` on any other value, so adding a constant requires extending that switch. |
