# model Specification

## Purpose

The `model` module is the core Eclipse plugin containing the Liquibase Ecore metamodel, EMF-generated Java classes, hand-written runtime API for programmatic model manipulation, and Epsilon EVL validation rules. It serves as the single source of truth for all Liquibase model operations in the JUDO platform.

## Architecture

The module has two code areas:

- **`src-gen/`** — Auto-generated EMF model classes, builders, helpers, and runtime wrapper. Regenerated from `model/liquibase.ecore` + `model/liquibase.genmodel` via the MWE2 workflow in `src/workflow/generateModel.mwe2`.
- **`src/main/java/`** — Hand-written runtime classes:
  - `LiquibaseModel` (generated by RuntimeModelGeneratorWorkflow) — Wrapper for building, loading, saving, and managing model instances
  - `LiquibaseUtils` — Optional-based query API for navigating model elements by ID/name
  - `LiquibaseEpsilonValidator` — Runs Epsilon EVL validation against a model instance
  - `LiquibaseNamespaceFixUriHandler` — XSLT-based URI handler that fixes XML namespaces on output to produce valid Liquibase XML
  - `LiquibaseModelStreamProvider` — Utility to serialize a `LiquibaseModel` to an `InputStream`

Key metamodel concepts (from `liquibase.ecore`): `databaseChangeLog`, `ChangeSet`, `CreateTable`, `Column`, `AddPrimaryKey`, `AddForeignKeyConstraint`, `AddNotNullConstraint`, `AddAutoIncrement`, `DropTable`, `DropColumn`.

## Requirements

### Requirement: Model building via builder pattern

The module SHALL provide a fluent builder API for constructing `LiquibaseModel` instances programmatically, including setting the model name, URI, and initial content.

#### Scenario: Build an empty model with a databaseChangeLog

- **GIVEN** no pre-existing model
- **WHEN** `LiquibaseModel.buildLiquibaseModel().name("test").build()` is called and content is added via `model.addContent(newdatabaseChangeLogBuilder().build())`
- **THEN** a valid `LiquibaseModel` is created with an accessible `ResourceSet` and `Resource`

### Requirement: Model element builders

The module SHALL provide generated builder classes (in `util.builder` package) for all Ecore model elements, accessible via static factory methods in `LiquibaseBuilders`.

#### Scenario: Build a ChangeSet with CreateTable and Column

- **WHEN** `newChangeSetBuilder().withId("cs-1").withAuthor("dev").build()` is called
- **THEN** a `ChangeSet` instance is created with the specified ID and author
- **WHEN** `newCreateTableBuilder().withTableName("USERS").withColumn(newColumnBuilder().withName("id").withType("ID")).build()` is called
- **THEN** a `CreateTable` instance is created with the specified table name and column

### Requirement: Model persistence

The module SHALL support saving a `LiquibaseModel` to a file or output stream, producing valid Liquibase XML with correct namespaces.

#### Scenario: Save model to file

- **GIVEN** a `LiquibaseModel` with content
- **WHEN** `model.saveLiquibaseModel(SaveArguments.liquibaseSaveArgumentsBuilder().file(outputFile).build())` is called
- **THEN** a file is written containing valid Liquibase XML with the `http://www.liquibase.org/xml/ns/dbchangelog` namespace

#### Scenario: Save model to output stream

- **GIVEN** a `LiquibaseModel` with content
- **WHEN** `model.saveLiquibaseModel(SaveArguments.liquibaseSaveArgumentsBuilder().outputStream(os))` is called
- **THEN** the output stream receives valid Liquibase XML

### Requirement: Model loading

The module SHALL support loading a `LiquibaseModel` from an input stream with a name and version.

#### Scenario: Load model from input stream

- **GIVEN** a serialized Liquibase XML stream
- **WHEN** `LiquibaseModel.loadLiquibaseModel(liquibaseLoadArgumentsBuilder().inputStream(is).name("demo").version("1.0"))` is called
- **THEN** a `LiquibaseModel` instance is created with the model content deserialized

### Requirement: Query API via LiquibaseUtils

`LiquibaseUtils` SHALL provide Optional-based query methods for navigating model elements by ID and name within a `ResourceSet`.

#### Scenario: Query ChangeSets

- **GIVEN** a model with two ChangeSets ("cs-1" and "cs-2")
- **WHEN** `utils.getChangeSets()` is called
- **THEN** an `Optional<EList<ChangeSet>>` containing both ChangeSets is returned
- **WHEN** `utils.getChangeSet("cs-1")` is called
- **THEN** an `Optional<ChangeSet>` containing the ChangeSet with id "cs-1" is returned

#### Scenario: Query CreateTables within a ChangeSet

- **GIVEN** a model with a ChangeSet containing two CreateTable elements
- **WHEN** `utils.getCreateTable("cs-1", "USERS")` is called
- **THEN** an `Optional<CreateTable>` for the "USERS" table is returned

#### Scenario: Query Columns within a CreateTable

- **GIVEN** a model with a ChangeSet containing a CreateTable with columns
- **WHEN** `utils.getColumn("cs-1", "USERS", "name")` is called
- **THEN** an `Optional<Column>` for the "name" column is returned

#### Scenario: Query primary keys

- **GIVEN** a model with a ChangeSet containing AddPrimaryKey elements
- **WHEN** `utils.getAddPrimaryKey("cs-1", "USERS", "_id")` is called
- **THEN** an `Optional<AddPrimaryKey>` matching the table and column is returned

#### Scenario: Query foreign key constraints

- **GIVEN** a model with a ChangeSet containing AddForeignKeyConstraint elements
- **WHEN** `utils.getAddForeignKeyConstraint("cs-1", "ORDERS", "USERS", "fk_user")` is called
- **THEN** an `Optional<AddForeignKeyConstraint>` matching the base table, referenced table, and constraint name is returned

#### Scenario: Query not-null constraints

- **GIVEN** a model with a ChangeSet containing AddNotNullConstraint elements
- **WHEN** `utils.getAddNotNullConstraint("cs-1", "USERS", "_id")` is called
- **THEN** an `Optional<AddNotNullConstraint>` matching the table and column is returned

#### Scenario: Empty model queries return empty Optionals

- **GIVEN** an empty model (no ChangeSets)
- **WHEN** any query method is called
- **THEN** `Optional.empty()` is returned

### Requirement: XML namespace fixing on output

`LiquibaseNamespaceFixUriHandler` SHALL transform EMF-serialized XML output via XSLT to ensure the root element is `<databaseChangeLog>` with the correct Liquibase namespace (`http://www.liquibase.org/xml/ns/dbchangelog`) and schema location.

#### Scenario: Namespace transformation on save

- **GIVEN** a `LiquibaseModel` being saved through `LiquibaseNamespaceFixUriHandler`
- **WHEN** the output stream is flushed
- **THEN** the XML is transformed so all elements use the `http://www.liquibase.org/xml/ns/dbchangelog` namespace

### Requirement: Epsilon validation

`LiquibaseEpsilonValidator` SHALL validate a `LiquibaseModel` against EVL rules, reporting errors and warnings.

#### Scenario: Validate a valid model

- **GIVEN** a valid `LiquibaseModel` and a validation script URI
- **WHEN** `LiquibaseEpsilonValidator.validateLiquibase(logger, model, scriptURI)` is called
- **THEN** validation completes without throwing an exception

#### Scenario: Validate with expected errors

- **GIVEN** a `LiquibaseModel` with known validation issues
- **WHEN** `validateLiquibase(logger, model, scriptURI, expectedErrors, expectedWarnings)` is called with matching expected errors
- **THEN** validation completes without throwing an exception

### Requirement: Code generation pipeline

The MWE2 workflow (`generateModel.mwe2`) SHALL generate four categories of code from the Ecore metamodel:

1. EMF model classes via `EcoreGenerator`
2. Navigation helper classes via `HelperGeneratorWorkflow`
3. Builder pattern classes via `BuilderGeneratorWorkflow`
4. Runtime model wrapper via `RuntimeModelGeneratorWorkflow`

#### Scenario: Full regeneration

- **GIVEN** the `model/model/liquibase.ecore` and `model/model/liquibase.genmodel` files
- **WHEN** `./mvnw -f model/pom.xml clean install` is executed
- **THEN** `src-gen/` is cleaned and regenerated with all four categories of generated code
